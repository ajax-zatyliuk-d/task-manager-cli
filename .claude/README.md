# Запуск наставника у Claude Code

У цьому проєкті підготовлені:

- `CLAUDE.md` у корені — постійна архітектура, контракти та команди.
- `.claude/rules/mentoring.md` — правила навчання та межі дозволу на зміни.
- `.claude/handoff.md` — датований стан, наступний крок і стартовий промпт.

Claude Code автоматично читає кореневий CLAUDE.md та правила без paths
із `.claude/rules/`. Звичайний файл handoff.md попроси прочитати явно;
він не є автоматично підключеним правилом. Окремий `/init` не потрібен
для створення вже підготовлених інструкцій.

## Початок роботи

Claude Code уже знайдено локально: версія 2.1.322 під час передачі
2026-11-12. У новому терміналі можна перевірити:

```sh
claude --version
cd /home/zatyliuk/Work/glib_test
claude
```

Використовуй корпоративний спосіб запуску та автентифікації, якщо він
відрізняється від цієї CLI-команди. Перевірка версії не перевіряє
автентифікацію чи підключення до внутрішнього провайдера.

У розмові відкрий `/memory`, щоб перевірити завантажені інструкції.
Через `/status` можна переглянути статус та джерела налаштувань,
зокрема керовану конфігурацію організації.

Потім встав стартовий промпт із `.claude/handoff.md` або короткий варіант:

```text
Прочитай CLAUDE.md, .claude/rules/mentoring.md та .claude/handoff.md.
Виконай стартове рев’ю з handoff: звір фактичний код із PDF, запусти
тести, поясни проблеми без редагування файлів. Якщо суттєвих проблем
немає — дай одне завдання на життєвий цикл контейнерів tags.
Код пишу я; відповідай українською.
```

## Що налаштовано

Додані лише файли інструкцій і передачі контексту. Не змінювалися
домашній каталог, корпоративні settings, авторизація, endpoint,
модель, дозволи або MCP. Ключі та інші облікові дані сюди не потрібні.
Для налаштування внутрішнього провайдера користуйся інструкцією IT;
конкретні параметри корпоративного середовища тут невідомі.

Це інструкції поведінки моделі, а не технічне блокування запису у файли.
